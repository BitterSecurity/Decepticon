# OpenShell selected-SDK admission correction

Fresh OSS main `44eb9032651c18df3f40e9f19a09e860d74ab43e` contains the new OpenShell default and first-run placeholder; the earlier default-HTTP/absent-extra findings are historical. Actual merged source still has three admission defects that were reproduced against frozen SDK0.1.6 and its real protobuf surface. This isolated correction changes no SaaS production artifact, VM, target authority, package version or release tag.

1. Daemon startup and readiness poll pass15.0 as `timeout_seconds`; the selected SDK assigns it to protobuf `Duration.seconds` (int64), raising TypeError before an exec RPC. Pass the same15-second bound as an integer. A real SDK/session and loopback gRPC fixture now serialize both requests. The fixture deliberately does not execute commands; it is not kernel evidence.
2. L7 `protocol` is a string field with vocabulary such as `rest`; rewriting it to `NETWORK_PROTOCOL_REST` creates a different, invalid protocol string. Preserve it while continuing to translate actual enforcement/access enums. The actual selected proto and serialization round trip retain `rest`.
3. Effective policy verification accepted every filesystem superset, so `/` or `/root` writes and other unexpected grants could pass. Permit only the selected supervisor's exact optional baseline additions, preserve every authored grant, then compare the entire protobuf after removing only those additions. Flags, version, unknown fields, network/process/Landlock content, additional grants and permission upgrades remain checked. Actual authenticated policy RPC refuses the overgrant before reading its ACK or obtaining an execution admission. This is a reproduced host admission defect, not an observed customer escape.

The permitted additions are sourced from [OpenShell0.1.6 supervisor ac7f615](https://github.com/NVIDIA/OpenShell/blob/ac7f615cd12d5cc49cb16eb1f5f10ffeb1e90f47/crates/openshell-supervisor/src/lib.rs): read-only `/usr`, `/lib`, `/etc`, `/app`, `/var/log`, `/proc`, `/dev/urandom`; read-write `/tmp`, `/dev/null`. Existing/missing runtime paths are optional; unknown additions fail closed and require explicit source review. There is no configurable broadening knob. Compiled scope and every other policy field are unchanged.

The first draft test used the wrong generated protobuf module for SandboxPolicy; its eleven fixture errors are retained and are not defect evidence. Correcting the fixture produces11 real failures and2 positive passes on unchanged main. After the correction, the initial affected-suite run has199 passes and two stale tests that expected the retired opt-in-only default. Updating them to exercise the actual default plus explicit opt-outs and a real `thread_id` retains first-run empty reads and execution refusal; the final affected suite passes207 cases without skips or errors.
