# OpenShell workspace binding collision correction

Current main44eb9032 shortened workspace identity to four hex characters and policy identity to eight. Two distinct synthetic workspace paths159/226 produce the same `dcpt-40c6-aaaaaaaa` locator after227 candidates. A local lifecycle reproduction then resolves distinct workspaces with identical approved policy to the same runtime. This is an observed resolver collision in a fixture, not an observed customer data exposure. Five regressions fail before correction.

The new19-character DNS locator hashes the **complete pair and approval** together: `dcpt-` plus14lowercase base32 characters (70bits) from a SHA256 over versioned canonical JSON containing the canonical absolute workspace path, complete policy hash and complete approved-document hash. Partial/noncanonical hashes are rejected. The short name is only a locator, never authority.

Creation also stores the entire256-bit digest as a52-character base32 `decepticon-binding` metadata label. Every new, reused, cached or renewed admission checks that label before and after effective-policy/loaded-ACK reads, alongside the existing runtime ID/generation, readiness and complete policy checks. Even a deliberately forced locator collision cannot attach another binding, create a second session, execute its daemon or overwrite the existing runtime. Missing/foreign metadata refuses before policy reads; mid-read label replacement refuses after the ACK. The actual selected SDK sends labels on CreateSandbox and retrieves them through authenticated loopback RPC; the fixture does not execute target commands.

Cache keys include canonical workspace, policy and approved-document identity. Changed approved bytes get a fresh runtime even if compilation yields identical policy. Same complete binding reconnects to its original runtime. Label removal invalidates cached execution before any new bridge call. This is the trusted local-host resolver contract; SaaS still must authenticate organization/run/custody and choose its own trusted workspace/resolver. A model-generated locator or receipt does not authorize access.

**Upgrade/data compatibility:** old names and unlabeled runtimes are not silently reused, adopted, relabeled, renamed or deleted. Preserve old session/data and plan an explicit migration through the trusted operator before new runs. No source update is activated by this PR. This supersedes the earlier claim that the4/8-character digests preserve noncollision: finite short names cannot guarantee that, so full identity must be verified independently. This admission check does not stop already-running background processes; the lifecycle controller retains cancellation/stop responsibility. The SDK's name-based exec is not represented as an atomic generation-conditional operation.
