# Decepticon version history

All notable changes to the Decepticon project. Format based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning
follows [Semantic Versioning](https://semver.org/) from `1.0.0`
onward (the `0.x` cycle is pre-stable per the core/framework/sdk split
design spec, §13.4).

Before opening or updating a PR, record its changes and PR link under
**Unreleased**. An open linked PR means proposed work; a merged linked PR means
integrated but unreleased work. Only dated release sections describe shipped work.
Maintain this single root `CHAGELOG.md`, preserving the full version history.
At release, move merged entries into a dated version section and add a comparison link.
Keep proposed and unmerged changes out of released sections.

## [Unreleased]

- Proposed, unreleased [local-first Rust design and research #1202](https://github.com/BitterSecurity/Decepticon/pull/1202): define native and Docker deployment options, file/DB ownership, framework maturity gates and a bounded custom-engine fallback, with migration/rollback constraints and local baseline evidence. Design only; no runtime, dependency, version or deployment change. [Design](docs/design/2026-11-16-local-first-rust.md), [research](docs/research/2026-11-16-agent-storage-frameworks.md).

- Proposed, unreleased [#1201](https://github.com/BitterSecurity/Decepticon/pull/1201): calculate the agent step budget from the latest operator message so follow-up requests can use tools after a long checkpointed conversation. Tool/interrupt continuations keep their current-turn cap. Twelve focused cases, including real offline LangChain/LangGraph checkpoint and interrupt execution, pass; the wider middleware/agent suite passes1,111cases with one explicitly skipped optional Transformers test. No version or package publication is performed.

- Root-published RoE bootstrap compatibility ([PR #1200](https://github.com/BitterSecurity/Decepticon/pull/1200)), not released: preserve an identical root-owned read-only scope context instead of failing its replacement under an unprivileged workload UID. Keep ownership/mode and exact bytes, bracket file/path identity, and retain ordinary atomic scope restoration. Real root/UID1500 baseline fails2cases; candidate passes7 with no skips. Full local suite6,323passed/16skipped (seven root cases separately qualified), required Ruff/format/type gate0errors. No policy bypass, version bump or deployment. [Evidence and limits](docs/verification/root-published-roe-bootstrap-20261116.md).

- Proposed [OpenShell admission successor fix #1199](https://github.com/BitterSecurity/Decepticon/pull/1199), not released: an explicit trusted callback can adopt a host-acknowledged successor before old expiry while preserving the backend and background jobs. Renewal must retain the complete execution/policy identity and match an independent current receipt; unknown renewal closes this client without replay. Per-backend serialization handles concurrent callers. Callbacks must publish their acknowledged receipt to the current reader before returning. Thirteen regressions fail on original main;251 connected cases pass with both SDK0.1.6 and0.1.7, and6,320 non-live cases pass with9 unqualified skips. Required Ruff/format/errors-only type gates pass (0errors,924reported warnings). [Evidence](docs/verification/openshell-admission-renewal-20261115.md).

- Proposed [plugin tool composition correction #1196](https://github.com/BitterSecurity/Decepticon/pull/1196): named tool replacements and disables also apply to additive plugin contributions, retaining the selected schema once and preventing a disabled tool from being added back. Preserve unrelated tools, role scoping, explicit-over-bundle precedence, existing safety checks and host-owned policy selection. All three focused regressions fail before the fix; 120 connected cases and the full local Python gate pass after it (6,292 passed, five explicitly unqualified skips; process exit zero), including actual LangChain tool invocation/schema checks. Full Ruff checks pass, and basedpyright reports zero errors with existing warnings. Seven hosted-schema consumer cases also pass against the actual OSS entry point. No public version or deployment change.

- Proposed [continuous-pentest follow-up designs #1184](https://github.com/BitterSecurity/Decepticon/pull/1184), not released. Design-only: two proposal docs for the remaining continuous-engagement work, no code. [External trigger start](docs/design/2026-11-12-external-trigger-start.md) — start an in-scope run from an authenticated external event (ASM/CI/alert) through a small trigger receiver that cannot widen scope. [Incremental re-assessment](docs/design/2026-11-12-incremental-reassessment.md) — each periodic run still scans from scratch (confirmed), with a baseline-diff overlay that reports only NEW/RESOLVED changes; the open design risk is the cross-run finding identity key. Both carry open decisions for review. Review clarified current tenant/approval/funding gates, OpenShell-only network authority, independent event delivery, comparable coverage before RESOLVED, tenant-scoped finding identity and ordered baseline writes. These remain proposals; merging the documents does not approve implementation choices or activate a service.

- Merged [scheduled engagements #1183](https://github.com/BitterSecurity/Decepticon/pull/1183), not released. `decepticon-cli schedule {create,list,delete}` starts engagement runs on the LangGraph server's native cron. `--mode reassess` (default) starts a fresh thread each tick (periodic re-assessment); `--mode campaign` continues one thread (a long engagement across scheduled slots, which `TimeWindowMiddleware` + `time-window-resume` keep inside its RoE window). `--multitask reject` skips a tick while a run is still active. Schedules are tagged so `list` reports only the ones this tool created. A scheduled run stays bound to the engagement's RoE and OpenShell policy. External-trigger start is a separate follow-up.
